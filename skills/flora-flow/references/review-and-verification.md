# 审查与验证

编写实现任务、安排审查或判断复审范围时读取。
本文件统一验证分工、委派约定和验收停止条件。

## 验证分工

| 执行者 | 检查范围 |
| --- | --- |
| 实现上下文 | ticket 验收场景、受影响包和编译检查 |
| 集成上下文 | 合并后的既定聚焦检查 |
| 独立审查上下文 | 合同与代码审查、所需完整门禁、证据核验 |

首次最终验收覆盖全部改动和完整门禁。
严格模式逐 ticket 独立验证，再执行最终验收。
逐 ticket 验证覆盖本 ticket 的全部验收条件。
跨包行为或仓库规则要求全仓检查时，执行全仓检查。
上下文切换本身不使通过证据失效。

同一检查已有有效证据时，记录复用依据。
复用前核对代码、测试、依赖、配置和环境输入。
输入发生变化时，重跑受影响的检查。
无法证明无影响时，扩大验证范围。
仓库强制检查仍按仓库规则执行。

## 实现任务模板

首条实现任务和后续修复任务都传入本段约定。
补齐实际命令、验收条件和仓库强制检查。

```text
模式：<fast 或 strict>
验收条件：<用户要求、最终公开符号、对应场景>
聚焦检查：<实际命令及其覆盖范围>
仓库强制检查：<命令，或无>

fast：直接按 ticket 实现，不调用 implement。
strict：读取 implement，按本任务的验证分工执行。
实现阶段运行聚焦检查，不运行内置独立 code-review。
全仓验证交给独立验证上下文。
若仓库规则要求实现阶段全仓检查，执行并记录依据。
若聚焦检查不足以验证改动，回报需扩大的范围与原因。
不要把“完整交付”解释为默认运行全仓测试。

返回验收条件、实际结果、证据路径和对应提交。
失败、跳过和未验证分别报告。
```

集成者安排扩大检查时，先记录影响范围和理由。
只因修复进入 `final-fix`，不扩大验证范围。

## 审查独立性与复审

审查者不实现或修复自己负责审查的改动。
首次审查使用独立上下文，按 `code-review` 审查。
修复后优先复用原审查者，保留 finding 和证据。
复审提供已审查 SHA、当前 SHA、差异和检查结果。
原审查者不可用或参与了实现时，更换审查者。
新审查者读取原 finding、证据和本次差异。

| 改动影响 | 复审和验证 |
| --- | --- |
| 文档、格式、注释、测试布局 | 定点复核差异，运行受影响检查 |
| 测试断言或测试同步 | 复核断言语义和被测行为，重跑对应场景 |
| 生产行为、公共合同或依赖边界 | 审查受影响调用路径，补充回归，扩大门禁 |
| 合并冲突改变语义 | 复核冲突区域及调用路径，重跑受影响门禁 |
| 影响无法界定 | 重新全量审查和验证 |

修改文档中的公共合同也属于合同变化。
文件类型不能代替影响判断。
复审者核验修复有效性及新增回归，不只关闭原 finding。
定点复审直接返回结论，无需重启完整 `code-review` 流程。
确需全量复审时，再调用 `code-review`。

证据复用记录原测试提交和当前提交之间的无影响依据。
最终报告区分原始检查与补充检查。
未经实际重跑，不声称在当前 SHA 执行了原检查。

## 验收停止条件

每项 finding 写明规范依据、影响和是否阻塞验收。
优先级标签不能单独决定是否阻塞。
公共合同错误、行为回归和强制检查失败必须阻塞。
风格建议和范围外改进记录为后续项，不自动创建修复循环。
仓库规定必须修复的规范项仍属于阻塞项。

所有验收条件通过且没有阻塞项时，结束验收。
保留非阻塞项及理由，不追求任意审查轮次或零建议。
相同失败再次出现时，核对修复依据和复现条件。
环境或范围外基线失败单列为受阻，不重复创建同类修复。
范围内缺陷继续修复，不能按轮次上限放行。
