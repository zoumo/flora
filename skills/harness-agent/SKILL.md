# Harness Agent

通过讨论收集项目事实与决策，再逐步补充 `harness/`。
目标是形成适合项目的工作上下文，不是安装全部模板。

## 最小集

只要求以下文件：

- `harness/AGENTS.md`：入口、规则适用范围、修改权限。
- `harness/index.md`：已有文档导航。
- 根 `AGENTS.md`：指向 harness 的入口，保留其他内容。

架构、代码布局、测试、技术栈与合同按需创建。
缺少可选文档不算初始化失败，不创建空文档来凑齐模板。
目标 `harness/` 不限制目录层级，默认优先平铺。
已有有效布局继续使用，不为匹配模板而移动文件。

## 准备

1. 确认目标仓库，未指定时使用当前仓库。
2. 读取目标路径适用的 `AGENTS.md`。
3. 检查分支、提交和未提交修改。
4. 读取已有 harness 入口，按任务读取其中的文档。

默认只分析 `harness/`，根 `AGENTS.md` 用于规则检查与入口接入。
用户明确要求整合外部资料时，读取指定范围并合并有价值的内容。
外部文档的迁移或删除须有对应授权。
不为了解决模板缺失而扫描项目全部文档。

## 渐进式询问

先从已有信息判断项目目标、使用者和 Agent 工作边界。
每轮只问 1 至 3 个当前需要解决的问题。
已有答案直接沿用，不要求用户重复回答。
问题可以提供候选项，但须允许用户表达其他选择。

按回答决定下一轮，不发送固定的完整问卷。
以下主题用于选择问题，不要求逐项问完：

- 项目目的、主要使用者与主要交付物。
- 架构、模块职责、依赖与接口边界。
- Agent 修改权限、协作方式与项目约束。
- 测试场景、验收条件与证据边界。
- 已用技术、选型理由与尚未确定的选择。

区分已确认事实、待确认事项和建议。
没有依据时不编造项目规则，不把候选技术写成已确认选型。
用户只要求讨论时，先讨论，不写文件。
用户要求初始化或补充时，展示拟写入内容与文件后写入。
用户已明确指定的内容无需重复确认。

每轮结束时收敛已确认内容、待确认事项与拟补充文件。
信息足够后完成当前范围，报告剩余事项，不要求一次补齐全部主题。
普通整理与链接修复自主完成。
权限边界或实质决策存在分歧时，只询问影响当前任务的事项。

## 模板

`templates/` 根目录保存跨语言模板，不设 `common/`。
语言模板按语言分目录，例如 `templates/golang/`。
只读取当前主题需要的模板，不扫描并安装全部模板。

| 主题 | 模板 |
| --- | --- |
| 最小入口 | `templates/AGENTS.md`、`templates/index.md` |
| 架构 | `templates/architecture.md` |
| 编码原则 | `templates/code-principles.md` |
| 测试与验收 | `templates/testing.md` |
| Go 项目性质与目录 | `templates/golang/directory-conventions.md` 及其中的目录模板 |
| Go 技术选型 | `templates/golang/technology-stack.md` |
| Go lint 配置 | `templates/golang/golangci-lint.yaml` |

模板提供内容起点，不规定目标路径，不要求逐字复制。
根据已确认内容调整正文，并按目标位置修复链接。
模板中的 Cobra、Viper、Lumberjack 是候选选型，不自动成为项目决定。
未选择的技术不作为项目约束写入。
配置模板仅在项目需要时提供，不自动启用或替换已有配置。

## 写入与合并

写入前保存拟修改文件的原始内容。
列出新增、合并、保留的文件，以及需要用户决定的差异。
先查 harness 索引与已有内容，复用等价文档，避免重复正文。
项目文档可以超出模板主题，按实际内容命名与组织。

保留项目设计、合同、元数据、导航和未提交修改。
已有规则和模板不同时，以已确认的项目决定为准。
规则含义存在冲突且无法从已有决定判断时，先收集裁决。
符号链接或非普通文件须保留，报告受阻路径，不自动替换。
禁止用空模板覆盖已有正文。

只把已确认的内容写成生效规则。
需要保留待确认事项时，单独标记并写明缺少什么决定。
更新索引，只链接实际存在的文档。
已有内容满足本次需求时，保留原文，不重复追加或重建目录。

将以下入口合并到根 `AGENTS.md`，等价入口不重复追加：

```markdown
## Agent Harness

开始工作前，读取并遵循 [harness 工作规则](harness/AGENTS.md)。
项目设计从 [harness 入口](harness/index.md)读取。
```

## 验证

前置条件：Python 3.9 或更新版本及 PyYAML。

```sh
python3 <skill-dir>/scripts/check.py --repo <repo>
```

脚本只要求最小集，检查已有 harness 文档的 OKF 格式与行内文件链接。
脚本不要求可选模板存在，不限制目标目录层级，不判断内容是否完整。
外部文件链接只检查目标是否存在，不读取外部正文。
依赖缺失时，使用已有环境或报告未验证。

对照本轮已确认内容，核对正文、索引、修改范围与原内容保留情况。
确认再次执行无需重复写入。
结果分为通过、失败和未验证，保留尚未确定的内容缺口。
文档检查不代表构建或运行验收通过。
