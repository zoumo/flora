# 基线与路径

准备单任务或集成工作区时，读取本文件。
准备子任务或临时验证工作区时，只读取“路径约束”。
子任务从已记录的集成分支派生，不自行选择远端基线。

## 选择基线

1. 核验仓库和候选提交。
   - 读取 Git 公共目录、当前分支、HEAD 和工作区状态。
   - 仓库或提交无法解析时，报告受阻。
   - HEAD 分离本身不阻塞创建任务分支。
2. 确定基线来源。
   - 用户指定提交、分支或已有 run 时，沿用指定基线。
   - 未指定时，优先采用当前任务分支。
   - 当前是主分支或 detached HEAD 时，核对上游与远端默认分支。
   - 多个候选影响不同交付范围且无法判定时，询问基线。
3. 检查远端新鲜度。
   - 远端存在且可访问时，用 `git fetch <remote>` 更新远端引用。
   - 记录远端分支、SHA、检查时间和差异。
   - 用户冻结的基线不随 fetch 改变。
   - 未冻结且当前基线仅落后目标远端时，新任务从远端提交派生。
   - 已有任务分支包含本地提交时，保留提交并评估同步范围。
   - 有分歧时，记录同步或继续冻结的理由。
4. 记录最终选择。
   - 返回基线 SHA、来源和远端检查结果。
   - 无远端或离线时，记录未检查原因。
   - 本地基线已明确时继续隔离开发，不声称远端最新。
   - 用户要求以最新远端为基准且无法核验时，报告受阻。

`fetch` 不改变已有工作区或任务分支。
同步分支出现冲突时，保留现场并交回调用方安排修复。
最终交付前复查目标分支差异，按调用方规则验证同步后的改动。

## 路径约束

准备工作区前，检查仓库测试对路径的约束。
涉及 Unix socket 或已知长路径失败时，优先缩短运行时 socket 目录。
需要缩短 worktree 时，在统一根目录使用短任务别名。
别名保留可读前缀，追加 Git 公共目录与任务标识的短哈希。
创建前检查重名，并将完整任务到路径的映射交回调用方。

复验需要短路径时，创建固定提交的临时验证工作区。
核对物理路径、提交、依赖和测试输入，记录环境差异。
工具或明确的任务限制阻止创建时，报告具体限制。
短路径通过只证明该环境的结果，原路径失败仍保留。
