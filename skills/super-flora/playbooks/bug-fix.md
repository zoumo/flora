# 缺陷修复

## 职责

恢复用户描述的预期行为，保留证据并避免无依据修改。

## 步骤

1. 明确正确行为、错误现象和完成标准。
2. 在原场景捕获失败证据。
3. 验证根因，排除没有运行时或代码证据的假设。
4. 选择最小修复。涉及多个交付单元时，按[分阶段实现](../references/delivery.md)执行。补必要的回归测试。
5. 重跑原失败场景。
6. 运行受影响检查并查看差异。

故障难以定位时，使用 `diagnosing-bugs`。
存在合适测试位置时，使用 `tdd`。

## 停止点

原故障已修复，失败证据和通过证据对应同一场景。
若只能确认部分行为，报告部分通过和未验证范围。
不能确认根因或无法复现时，停在诊断结论，不把猜测记为修复。
