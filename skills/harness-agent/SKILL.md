# Harness Agent

本文件指导初始化与合并，模板指导后续仓库开发。
`templates/` 路径相对于目标仓库的 `harness/`。
模板必须安装到对应的 `harness/` 路径。

文档扫描、内容比较和合并只限于 `harness/`。
不分析 `docs/`、`specs/` 或其他目录中的项目文档。
外部同类文档不影响模板安装，也不能替代模板文件。
根 `AGENTS.md` 只接入 harness 入口，保留其他内容。

## 准备

1. 确认目标仓库，未指定时使用当前仓库。
2. 读取目标路径适用的 `AGENTS.md`。
3. 检查分支、提交和未提交修改。
4. 读取 `harness/` 内的已有入口与文档。
5. 扫描并读取 `templates/` 的全部文件。
6. 保存拟修改文件的原始内容。

初始化授权包含模板安装和根入口修改。
目标仓库的更严格限制继续有效。
用户只要求方案时，只输出计划。

## 合并

写入前，逐文件对照模板与目标内容。
只比较模板对应的 `harness/` 路径。
模板路径缺失时，安装模板，不搜索其他目录中的等价文档。
已有索引指向外部文档时，保留引用，但不读取或合并外部正文。
索引须同时包含模板要求的内部链接，外部引用不能替代内部链接。

| 目标状态 | 动作 |
| --- | --- |
| 模板对应路径无文件 | 复制模板，保留模板相对路径 |
| 模板对应文件已有等价规则 | 保留原文 |
| 缺少规则且无冲突 | 只补充缺失部分 |
| 语义冲突 | 列出差异，等待用户裁决 |
| 符号链接或非普通文件 | 保留并报告阻碍 |

存在冲突或路径阻碍时，暂停全部写入。
用户已裁决的冲突按裁决处理，无需重复确认。
计划须列出新增、合并、保留和需裁决的文件。
按计划安装文件，并补齐必需的索引链接。

保留 `harness/` 内的项目设计、合同、元数据、导航和未提交修改。
已有文件不要求与模板逐字相同。
禁止用空模板覆盖已有正文。
harness 内只按模板新增文档。
迁移项目其他文档须作为独立任务处理。
已有规则要求同步日志时，只修改 `harness/` 内的必需记录。

将以下入口合并到根 `AGENTS.md`。
保留根文件其他内容，等价入口不重复追加。

```markdown
## Agent Harness

开始工作前，读取并遵循 [harness 工作规则](harness/AGENTS.md)。
项目设计从 [harness 入口](harness/index.md)读取。
```

## 验证

1. 运行文档校验。
2. 核对差异是否符合计划。
3. 确认项目内容得到保留。
4. 再次对照模板，确认无需重复修改。
5. 报告变更、冲突和验证结果。

前置条件：Python 3.9 或更新版本及 PyYAML。

```sh
python3 <skill-dir>/scripts/check.py --repo <repo>
```

脚本要求全部模板文件位于对应的 `harness/` 路径。
脚本检查基础文件、OKF 结构和行内文件链接。
概念文档的 `type`、`title`、`status` 须为非空字符串。
缺失、空值或类型错误均导致检查失败。

脚本跳过依赖目录，不判断合并语义。
外部文件链接只检查目标是否存在，不读取目标正文。
依赖缺失时，使用已有环境或报告未验证。
已有文档校验失败时，报告路径，保留修改边界。
结果分为通过、失败和未验证。
文档检查不代表构建或运行验收通过。
