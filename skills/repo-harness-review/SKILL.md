# Repo Harness Review

评估仓库现有设计、契约和工程机制。默认评估全仓库的 `HEAD`，用中文报告。用户指定模块时，纳入对模块生效的共享规则。

## 执行步骤

1. **固定快照。** 记录仓库绝对路径、提交 SHA、工作区状态和范围。如果评估工作区，列出纳入的本地改动。
2. **分派评估。** 为 6 个领域各派 1 个独立 Agent。并发额度不足时分批派发。附上对应的领域文档、共用快照、范围和评分规则。各 Agent 按报告格式逐项回传。

   - [文档](references/documentation.md)
   - [代码](references/code.md)
   - [测试分层](references/testing.md)
   - [可观测性](references/observability.md)
   - [可验证性](references/verifiability.md)
   - [发布与升级](references/release-upgrade.md)

3. **核对回传。** 主 Agent 核对快照、证据和评分。汇总前，对照主 Agent 和各领域 Agent 的实际执行记录，补齐漏记的运行证据。把评估漏项交回原 Agent。证据冲突时，核对适用范围并说明取舍依据。
4. **汇总报告。** 覆盖全部维度。如果缺少领域回传，将报告标为未完成，并列出缺失领域。

## 取证与评分

先查源码、文档、测试、配置和已有运行记录。仅当现有证据不足且执行能补足时，运行最小命令或定向测试。执行前写明待证维度和缺口。主 Agent 为同一验证目标只安排 1 名执行者。各 Agent 复用结果。默认省略全量回归。

执行者记录命令、环境、结果和证明范围。

引用 `路径:行号`、配置键或已有记录。写明版本和运行边界。区分公开承诺、可执行机制和强制约束。代码与契约冲突时，引用双方证据。

- 报告有证据的权限、外部输入、密钥和用户数据缺口。按授权开展防御性检查。
- 按需查性能预算、负载模型和基准回归。性能信号归入可观测性。

### 必要项完备度

测试分层和可观测性分别计算完备度。先按用户要求和仓库职责确定必要项，再盘点现状。逐项列出必要性依据、状态和证据。

- 必要项已存在得 1 分，确认缺失得 0 分。缺失时列出已查入口。
- 必要项证据不足标 `?`，计入必要项数。有 `?` 时列出已确认分和待定项，总分待定。
- 非必要项标 `N/A` 并说明理由。全部非必要时，完备度标 `N/A`。
- 完备度为已确认存在的必要项数除以必要项数。每个领域单列得分和满分。

### 能力质量

按以下规则为各领域的能力维度评分。合并和发布的强制门禁只在「发布与升级」的 Release Gates and Provenance 维度评分。必要项缺失已体现在完备度中。若缺失也影响能力质量，指出无法验证的行为或无法回答的问题，并引用证据。

| 分数 | 判定 |
| --- | --- |
| `0` | 有反证，或核对负责入口后确认机制缺失。 |
| `1` | 仅有约定或间接证据。 |
| `2` | 机制可用，覆盖或接入有缺口。 |
| `3` | 机制满足维度要求。需要强制约束时，能追到生效规则。 |
| `?` | 证据不足。列出已查位置和缺少的证据。 |
| `N/A` | 维度超出仓库职责。说明理由。 |

领域分取已评分维度的平均值，保留 1 位小数。报告已评分数和适用维度数。`?` 计入适用数。`N/A` 单列。适用项均无分时，标 `?`。没有适用项时，标 `N/A`。

能力质量总分只汇总已评分能力维度的原始分。适用满分为适用维度数乘以 3。有 `?` 时，注明总分未定。

## 报告格式

- **评估范围。** 列出快照、范围和取证限制。
- **评分总览。** 并列报告测试分层和可观测性各自的必要项完备度与能力质量原始分。两项独立计分。列出全仓能力质量的原始得分、适用满分、得分率和评分覆盖率。列出各领域的分数、覆盖率、主要优点和缺口。
- **维度明细。** 逐项列出分数、优点、缺口、证据和限制。区分本轮执行、已有运行记录和静态证据。
- **优先改进。** 对影响最大的已确认缺口，给出一项最小改进、预期效果和验收条件。缺口尚未确认时，写明补证据的入口。
