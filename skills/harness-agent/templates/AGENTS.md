# Harness 工作规则

开始工作前，读取 [harness 入口](index.md)。
按任务读取索引指向的文档，并遵循已确认的项目约束。

## 写入权限

写入须有人类明确要求或事先同意，普通开发任务不自动授权。
授权包含必需的引用与索引同步，工具写入同样受限。

## 文档组织

`harness/` 保存已确认的工作规则、架构、设计与合同。
文件位置按项目需要确定，不强制目录层级。
同一内容保留一份正文，其他入口使用链接。
已有项目约束优先于通用模板。

## 内容与格式

正文描述已确认的目标，不把推测写成项目规则。
待确认事项单独标记，不作为已生效的约束。
内容变化直接更新正文，历史由 Git 保存。
设计已确认不代表实现已完成。

文档采用 Open Knowledge Format（OKF）v0.2。
概念文档须有非空的 `type`、`title` 和 `status` 元数据。
根索引声明 `okf_version: "0.2"`，子索引不含元数据。
内部文档使用相对链接。
