# 基线与路径

## 基线选择

1. 如果用户指定提交、分支或已有 run，沿用指定基线。
   否则优先采用当前任务分支。当前是主分支或 detached `HEAD` 时，核对上游和远端默认分支。
   如果候选提交影响交付范围且无法判定，询问基线。
2. 如果远端可访问，运行 `git fetch <remote>`。
   记录远端分支、SHA、检查时间和差异。
   如果用户冻结基线，保留冻结的提交。
   如果基线未冻结且只落后目标远端，新任务从远端提交派生。
   如果存在本地提交，保留提交。如果分支有分歧，记录同步或冻结的理由。
3. 如果无法检查远端，记录原因。
   如果本地基线明确，可继续使用本地基线。
   如果用户要求最新远端提交，报告受阻。
4. 交付前复查目标分支差异，按调用方要求验证同步后的改动。

## 短路径

1. 如果 Unix socket 路径过长，优先缩短 socket 目录。
2. 如果必须缩短 worktree 路径，在 `workspace_root` 下用短别名。
   别名由可读前缀和短哈希组成。哈希使用 Git 公共目录和任务标识。
   检查重名，并向调用方返回任务与路径的对应关系。
3. 如果需要短路径复验，用固定提交创建临时工作区。
   核对物理路径、提交、依赖和测试输入。记录环境差异和两种路径的结果。
   如果无法创建，报告具体限制。
