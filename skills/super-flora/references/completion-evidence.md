# 完成证据

在确定完成标准、复用验证结果或准备最终报告时读取本文件。
证据必须对应最终产物或最终状态。

| 交付物 | 必要证据 |
| --- | --- |
| 调查结论 | 来源、关键事实、推断和未确认项 |
| 设计方案 | 问题、决定、取舍、风险和验证方式 |
| 缺陷修复 | 修复前失败证据、根因、修复后同场景的通过证据 |
| 功能 | 验收条件及对应实际结果 |
| 重构 | 行为基线和改动后一致性证据 |
| 评审 | 每项 finding 的依据、影响和是否阻塞 |
| 操作 | 实际操作结果和权威状态读回 |
| 写作 | 目标产物、事实来源和可读取检查 |

## 证据状态

测试、部署或逐项验收需要标记验证结果时，使用以下状态。
调查和设计直接给出来源、判断和未确认项。

- `passed`：检查已运行，并满足完成标准。
- `failed`：检查已运行，结果不满足完成标准。
- `partial`：仅部分范围已验证，写明缺失部分。
- `unverified`：未运行或现有证据不能证明结果。

未验证、受阻和不确定都不能记为 `passed`。

## 复用

复用已有证据前先核对代码、输入、依赖、配置和环境。
输入发生变化时，重跑受影响检查。
无法证明不受影响时，扩大验证范围。
最终报告区分本次检查和复用证据。
