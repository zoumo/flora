# 完成证据

在选中 playbook 确定完成证据时读取本文件。
分析、设计或规划请求在输出结论前读取。
按任务确定完成证据。
快速模式和严格模式把要求写入规范及每张 ticket。
简单修复在当前上下文记录要求。

| 任务 | 必须提供的证据 |
| --- | --- |
| 修复缺陷 | 修复前的失败证据，以及修复后同一场景的通过证据 |
| 新增或改变行为 | 验收条件，以及对应的实际验证结果 |
| 重构 | 改动前的行为基线，以及改动后的行为一致性证据 |
| 性能改进 | 相同场景下的基线、改动后数据和测量方法 |
| 分析或设计 | 来源、结论、取舍和未确认项 |

修复前先捕获失败证据。重构前先保存行为基线。
证据必须对应最终交付的提交或工作区。
改动使证据失效时，重新验证受影响的验收条件。
未验证、验证受阻和结果不确定都不能记为通过。
最终报告列出验收结果、证据位置和未完成项。

## 需求到证据

规范和 ticket 保留用户明确要求的符号、值及例外。
使用验收表逐项关联要求与证据：

| 用户要求或合同 | 最终行为或符号 | 验证场景 | 实际结果与证据位置 |
| --- | --- | --- | --- |
| `<要求>` | `<行为、字段或配置值>` | `<检查命令或观察方式>` | `<结果、提交和日志>` |

名称变更分别检查公开字段、配置值和文档。
保留协议字段时，在表中写明例外。
最终验收对照原要求，不只搜索旧符号。

安排验证或复用证据时，读取[审查与验证](review-and-verification.md)。
