# Flora Git Flow

调用方提供仓库、任务标识、操作和资源负责人。
复用已有资源时，调用方提供绝对路径、分支和预期 `HEAD`。
资源负责人创建工作区，并串行刷新、合并和清理。
调用方负责分配工作区、组织实现、验收和记录资源归属。

## 操作流程

1. 核验仓库、worktree 登记、分支和 `HEAD`。
   比较 Git 公共目录的绝对路径，确认仓库归属。
   如果归属不明、`HEAD` 不符或隔离受阻，停止并报告。
2. 按本次操作执行。
   - 准备工作区时，按下节复用或创建。验收使用待验证的工作区。
   - 刷新、合并或清理时，读取[集成与清理](references/integration.md)。
   - 保留已有改动。禁止自动 stash、reset 或覆盖。
3. 从 Git 核验实际状态。返回绝对路径、分支、实际 `HEAD` 和完成证据。
   准备工作区时，另附 `workspace_root` 和基线 SHA。
   对单任务和集成工作区，附上基线来源和远端检查记录。
   如果部分成功，报告已完成操作、剩余资源和原因。恢复时只补做未完成项。

## 准备工作区

1. 确定基线和路径。单任务和集成工作区按[基线选择](references/baseline.md#基线选择)执行。
   子任务从本地目标分支当前 `HEAD` 派生。记录该提交。
   如果无法解析基线提交，停止并报告。
   创建前检查测试的路径约束。如果需要缩短路径，查阅[短路径](references/baseline.md#短路径)。
2. 查找并复用符合条件的 worktree。
   如果工作区有改动，确认归属后才能写入。
   如果复用的集成工作区有改动，报告隔离受阻。
3. 如果没有可复用的工作区，从基线创建分支和 worktree。
   新 worktree 只包含基线提交，未提交改动留在原工作区。
   如果分支已创建但 worktree 创建失败，报告残留分支。
   任务结束后保留任务分支和工作区，按授权另行合并或清理。

## 默认路径和分支

优先使用用户指定值，其次采用仓库约定。已有工作区沿用原路径。

`workspace_root` 默认是 `~/.worktrees/<repo-key>/<slug>`。
`<repo-key>` 取主工作区目录名。同名仓库追加来源标识。
`<slug>` 使用小写字母、数字和短横线。调用工具前将路径展开为绝对路径。

| 工作区 | `workspace_root` 下的目录 | 默认分支 |
| --- | --- | --- |
| 单任务 | `task` | `codex-<slug>` |
| 集成 | `integration` | 当前任务分支。当前是主分支或 detached `HEAD` 时，新建 `codex-<slug>` |
| 子任务 | `<id>-<task-slug>` | `<target-branch>-<id>-<task-slug>` |

将任务改动提交到任务分支。禁止直接提交到 `main` 或 `master`。
